compatibility patch in `patches/herdr/`, applied to Herdr source commit

## Blocker 2: no existing path launches dependent B with a prompt

This is a code finding, not a runtime observation. B needs a queued
`integrated_commit` edge on A, and its signed contract must list the same edge
(`contract_binding::queue_matches_with_budget`).

- **Operator draft, sign and reserve** (`launch_preparation::inputs`) always
  seals `dependencies: Vec::new()`. When factory admission is off,
  `admit_prepared` (`src/store/reservations.rs`) refuses any queued edge
  ("dependency evidence producers are not available"). When it is on, it
  refuses a mismatch in the edge count ("task is not ready for reservation").
  So an operator can never reserve a dependent task.
- **Factory admission and delegated reservation** do fill the dependencies and
  pin repositories from the contract's `base_oid`, but `seal_admission_inputs`
  sets `memory: None`. The worker brief needs a bound knowledge snapshot
  (`attempt_knowledge_snapshot_with_budget`: "attempt knowledge binding
  missing"). A dependent launched this way would start without a prompt.
- For a single `integrated_commit` edge, `prove_integrated_base` skips the
  ancestry check (it only checks groups of two or more). B's base would
  therefore be whatever its contract or selection pins. Nothing proves that
  base contains A's integrated commit.
