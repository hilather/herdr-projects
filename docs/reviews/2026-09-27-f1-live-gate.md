## Attempts and findings

- The first attempt (before #51/#52) was blocked: no stock-Herdr launch, no prompted dependent.
- Live attempt 1 failed at B. With both workers on one Herdr server, start
  naming refuses: its fence compares the whole `agent.list`, and A's entry
  changed. Recovery then loops on "native worker name mismatch"
  (`canonical_worker/start.rs`, `allow_name=false`). Attempt 2 gives each
  binding its own server. Not fixed here.
- Fixed as glue: stock Herdr does not run typed text ending in `\n`, so the
  exec line is now sent with an `Enter` key. The 20 s preparation budget was
  too short to hash the 262 MB Codex binary about five times; it is now 60 s.
  The Codex `--version` probe ran without HOME and wrote helper links into the
  account's `~/.codex/tmp/arg0`; it now gets the execution home.
- Codex `workspace-write` makes Git metadata (even a worktree's gitdir)
  read-only, so the workers ran `danger-full-access` in the disposable home.
- Stopping a finished worker means cancelling it, which marks its task cancelled
  and blocks dependents (`predecessor_failed`); A ran until B launched.
  Integration rechecks only the first accepted policy by id.
