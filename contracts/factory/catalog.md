# Factory contract implementation map

This maps the logical entities in the factory plan's `14-contract-catalog.md`
to this checkout. It is an implementation inventory, not F0.4 acceptance.
The common envelope, complete digest-vector set, and independent authority review
remain incomplete. A table or Rust type does not establish production wiring.

Paths below are relative to this document. SQLite schema versions are independent
of document versions. Schemas 42 and 43 are local corrections, not published
compatibility promises. Original review evidence is retained separately.

## Serialization and compatibility evidence

Optional delivery retirement has its own strict version-1
`WorkerUpdateSupersession` request and immutable receipt in
[memory_supersession.rs](../../src/store/memory_supersession.rs). It references
the same worker's exact applied replacement receipt and preserves the obsolete
change's history. It is not another `seen` or `applied` disposition and does not
count as old-revision consumption. The
[workflow](../../docs/factory/memory-packages.md) documents the eligibility,
idempotency and mandatory-change boundary.

| Evidence | What it proves | What it does not prove |
| --- | --- | --- |
| [Task contract vectors](task-contract.md), [domain cases](../../src/domain/factory/contract_tests.rs) | Fixed SHA-1/SHA-256 document bytes and content digests; legacy/explicit dependency policy references; nested critical-field rejection | Signature authority or a new canonical-set encoding for retained version-1 documents |
| [Delegation v2 JSON](delegation-v2.json), [SHA-256](delegation-v2.sha256), [domain cases](../../src/domain/factory/delegation_tests.rs) | Fixed raw bytes/hash; version separation, sorted bounded references, explicit Git format and invalid-field cases | Operational delegated admission or vectors for the other catalog entities |
| [Historical launch inputs](../../tests/fixtures/launch-inputs-v1.json), [attempt inputs](../../src/domain/attempt_inputs.rs) | Retained historical shape; optional contract binding omits absent fields to preserve old serialization | A universal mutation envelope or all effect-generation/incarnation requirements |
| [Historical schema builder](../../src/store/test_schema.rs), [migration tests](../../src/migration/tests.rs) | Genuine migration prefixes, explicit upgrades and rollback regression coverage | A demonstrated live canonical backup/restore drill |
| [Original review reproductions](../../docs/reviews/factory-bd6433d-evidence/), [correction tracking](../../docs/reviews/2026-09-26-factory-corrections.md) | Traceable bug evidence and scoped validation results | Full plan acceptance or unperformed live gates |

Signed task/delegation documents retain and hash the verified raw bytes. Whitespace
changes therefore change their identity; this is not a claim of universal JSON
canonicalization. Other types, including `BudgetPolicy`, hash their defined
serialized representation. Each contract needs its own documented encoding and
golden vector before claiming catalog-wide canonical compatibility.

The common catalog envelope is not uniformly implemented. Existing APIs mix
expected heads, typed entity revisions, raw document keys and project-store paths.
This map deliberately does not label those as equivalent to a universal
`store_incarnation`/actor/delegation/request envelope. Restore fencing, causal event
references, typed blockers and all API bounds require contract-specific review.
